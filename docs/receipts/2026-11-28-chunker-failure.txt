problem
  docling-jobkit process_chunkable_results caught every chunker exception,
  logged it, counted num_failed and returned a successful ChunkedDocumentResult
  with zero chunks and the document status SUCCESS. Upstream marks this with a
  TODO. With an expired HF_TOKEN the tokenizer download returned 401 and REST
  and gRPC both answered success with 0 chunks.

approach
  Fix in jobkit (the exception is discarded there, serve cannot recover it),
  serve consumes the fork commit by git pin. Upstream merges stay easy: the
  jobkit change is confined to process_chunkable_results, public_errors.py and
  the local worker failure branch; the serve change is one pyproject source
  line, the lock entry and one branch in GET /v1/result.

caveats
  - Partial chunk failures in a multi-document request still return a
    chunk response, with the failed document status FAILURE and a typed error
    on that document. Only "no document could be chunked" fails the task.
  - Async REST result for a failed task is HTTP 200 with a TaskFailureResult
    body, the existing convention for stored failures. Sync REST is HTTP 500.
  - gRPC keeps status OK and reports the failure in the typed result arm, the
    existing convention for task-scope failures. No gRPC abort code is used.
  - serve pins the fork jobkit by git rev. Return to the PyPI release once
    upstream propagates chunk errors.
  - tests/test_grpc_serve.py::test_chunk_hybrid_source_sync now fails loudly
    (failure arm, no chunks) when HF_TOKEN is rejected, instead of passing
    through an empty success.
